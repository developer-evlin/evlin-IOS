# Handover — 2026-10-03

What changed between `5587cc0` (23 September, the previous handover) and
today. **None of it is committed or deployed yet.** It's written for
whoever picks this up next, including an agent with no memory of the work.

Read [`CLAUDE.md`](../CLAUDE.md) first for how the repo works. This file is
about what's different and what's left.

---

## 1. The latest change: Library, comics and voice notes removed

The most recent piece of work removed three features completely.

**The Library, on both sides.**
- Parent Library tab (three slide lessons, the lesson reader, topic tiles) and
  kid Library tab (three origami guides) are gone. Parent tabs are now Home,
  Calendar, Chat, Settings; kid tabs are Task, Calendar.
- 61 images deleted: 18 origami guide panels, 42 comic panels (`KidT1–9`,
  `TantrumCalm`) and an unused mascot. The asset catalog now holds only the
  app icon and accent colour.
- Kept on purpose: the four onboarding animations and the Screen Time PIN
  tutorial video. Onboarding still uses them.

**Comics (backend).**
- The `ComicGuide`, `ComicPanel`, `SlideLesson` and `LessonSlide` models are
  gone. Their tables (`app.comic_guides`, `app.comic_panels`,
  `app.slide_lessons`, `app.lesson_slides`, `content.comics`) were empty in
  production and are dropped on the next deploy.
- The `/content` upload/download routes are gone. No client called them. The
  `R2_PUBLIC_BUCKET_NAME` setting only served them, so it was removed from
  `storage.py`, `render.yaml` and `.env.example`.

**Voice notes.**
- Kid: no recorder on the task screen or the "Ask to skip" sheet. Asking to
  skip now needs a typed reason.
- Parent: no voice player on the review card, and the redo sheet's voice
  toggle is gone. That toggle was a mock that never recorded anything.
- App: the microphone permission is gone from `project.yml`.
- Backend:
  - New uploads must be photos (`SubmissionCreate` validates it).
  - Tasks take `photo` or `none`. Any other value is stored as `none`.
  - The `submissions.duration_seconds` column (a recording's length) is
    dropped.
- **Data:** production has one historical voice submission. It's kept as a
  row, because `app.submissions` still allows `voice`, but nothing in the app
  plays it any more. `SubmissionCreate` and `SubmissionResponse` are separate
  classes on purpose, so listing that task doesn't fail validation.
  `test_an_old_voice_submission_still_lists` guards it.

**Migration order on deploy** (all in `main.py` `_MIGRATIONS`, idempotent):
1. Tasks `either` → `photo`, `voice` → `none`.
2. Drop `submissions.duration_seconds`.
3. Rebuild the `submission_kind` constraint as `('none','photo')`.
4. Drop the five library tables.

All of this was run twice on a production-shaped local Postgres: everything
drops, the conversions apply, the constraint refuses `voice` and `either`, and
the second run is clean.

### Added or changed

**The AI's tools live in [`evlin-backend/tool_calls/`](../evlin-backend/tool_calls/README.md).**
- It has exactly three: `draft_task`, `draft_event`, `ask_follow_up`.
- `chat.py` reads only what that package exports, so the tool list, the
  prompt's description of it and the replies can't drift apart.
- The model still never writes: every tool pre-fills a card, and the parent's
  tap creates.
- The system prompt now says honestly that blocking, bedtime and extra screen
  time are done elsewhere in the app. It used to claim it couldn't add
  calendar events, even after `draft_event` existed.

**Memory stays, as architecture with no UI.**
- `child_memory` facts are injected into the prompt, capped at 40 newest.
  Dedup still checks all of them.
- Deleting a chat thread hard-deletes the facts learned from it.

**Live updates replace polling.**
- `GET /live` is a server-sent-events stream (`live_updates.py`,
  `routers/live.py`). It carries only "something changed, sync now".
- An SQLAlchemy commit hook works out which child and which parents a
  transaction touched, so no route publishes by hand.
- The hook is silent for chat and memory writes, and for objects with no net
  change, so idempotent writes can't cause a sync loop.
- The 10s kid poll and 15s parent poll are gone. `LiveUpdates.swift` holds the
  stream while the app is in the foreground.
- `/health` reports `live_connections`.
- The in-memory broker is single-process by design. Render runs one process.

**Sync coalescing fix.** `AppSync.syncBackendData` runs one more pass if called
mid-sync. Previously, a change committed during a sync could be missed until
the next event.

**Chat opens on a new thread.** Past threads stay in the sidebar.

**Kid hand-in fix.**
- "All done!" now submits immediately. It used to submit only via "Back to
  today", so the Back button or a swipe silently dropped the submission.
- This is why "Introduction to Stars" sat at pending while the kid thought it
  was handed in.

**App blocking connected to the database**, with no Apple identifiers
anywhere:
- `apps` is a catalog of 21 apps with aliases, seeded by migration.
  `child_apps` is each child's lockable list. `children.timezone` is reported
  by the kid device, only when it changes.
- `app_blocks` holds one row per app, in four kinds: `duration` (fixed
  `ends_at`), `until_task` (resolves on approval), `indefinite`, `scheduled`
  (weekday codes plus a child-local window; overnight windows belong to the
  day they start).
- `blocks.py` computes state and never writes it. `resolved` is only ever a
  decision: `task_approved` or `parent_lifted`.
- `POST /app-blocks/{id}/lift` replaces the hard `DELETE`, so history stays.
- The Block Apps card is opened from the chat's "Block an app" tile. The AI
  drafted blocks for about a week, then that was taken off it. The card
  stays; the AI tools don't.
- `GET /children/{id}/policy` (`policy.py`) is the one combined answer: lock
  reasons, the apps a lock covers, blocked-now, scheduled blocks, allowance,
  and an etag. The kid's `EnforcementState` reads the cached policy and falls
  back to local computation on a new day offline.

**Correctness fixes found along the way:**
- Time grants are dated on the child's local day. The server's UTC date used
  to put a Pacific-evening bonus on tomorrow.
- `daily_limit_enabled = false` now means "no limit" in the policy. It was
  ignored before.
- Approving an already-approved occurrence returns 409. It used to pay the
  bonus twice.
- The kid's photo-flow submit (see the hand-in fix above).

## 3. Before deploying

1. **Back up Supabase.** The migrations drop tables and columns, and that
   can't be undone.
2. **Deploy the backend before shipping an app build.** The new app removed
   polling and depends on `/live`, `/apps`, the new `/app-blocks` body and
   `/policy`.
3. **Commit carefully.** The tree mixes this work with older uncommitted edits
   that weren't part of it:
   - onboarding files
   - `ScreenTimePINVideoView`
   - the `NSCache` change in `AppCatalogData`
   - `requirements.txt`
   - the deleted `restart-swift.sh`
   - untracked debug scripts in `evlin-backend/` (`test_*.py`, `patch_*.py`,
     `debug_register.py`, `get_user.py`, `create_tables.py`, `uvicorn.log`)

   Review these before staging them.
4. **Render environment:** `YOUTUBE_API_KEY` and `R2_PUBLIC_BUCKET_NAME` are no
   longer read and can be deleted. `GEMINI_API_KEY` must be set or chat
   returns 503.
5. **After deploying:** `curl /health`. Expect no `missing_columns`, and
   `live_connections` above 0 while an app is open. If it stays 0, Render is
   buffering the stream.

## 4. Traps

- **The simulator may be running a stale app.** On 2 October the iPhone 17
  simulator had `com.evlin.io` installed, built 24 September, which still
  shows milestones, courses and reflections. The project builds
  `com.evlin.app`. Rebuild and delete the old copy. If `com.evlin.io` is
  deliberate (signing), put it in `project.yml`, because `xcodegen generate`
  rewrites the project file from it.
- **`evlin-tables.sql` can't be applied cleanly by `init_db.py`.** Its first
  statement needs Supabase's `vector` extension, and `init_db` splits on `;`,
  including semicolons inside comments. It's untracked locally. Production
  was not built from it alone.
- **Tests build their schema from `models.py`, never from `_MIGRATIONS`.**
  `tests/test_migrations.py` guards the newer tables and the drops. Postgres-only
  SQL (jsonb functions, `make_interval`, `DO $$` blocks) has to be checked on a
  real Postgres. Homebrew `postgresql@16` works: `initdb` into a temp dir and
  listen on TCP only, because the scratch path is too long for a Unix socket.
- **Your shell exports an old `GEMINI_API_KEY`** (`AQ.` prefix) that shadows
  `.env`. `load_dotenv` never overrides.
- **SourceKit shows false "cannot find type" errors** in this repo. Trust
  `xcodebuild`.

## 5. Open

- **Security bug, unfixed.** Family-wide calendar events (`child_id NULL`)
  have no owner, so every parent can read, edit and delete every family's.
  See `routers/calendar.py` `_event_for_parent` and `get_child_events`. The
  fix needs an owner column.
- **No lockable-list editor.** `APIClient.setChildApps` and
  `PUT /children/{id}/apps` exist, but no screen uses them. Apps get onto a
  child's list only via "add and block".
- **Real Screen Time enforcement and push notifications** are planned, not
  built. The policy endpoint is what an enforcement layer would consume.
- **Older docs** in this folder describe features that no longer exist. Each
  has a note at the top saying which parts.
- **Not seen on a device.** Every UI change here was checked with
  `xcodebuild` only.
